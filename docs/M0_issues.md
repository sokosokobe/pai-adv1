## [実装] 開発基盤の整備

- **種別**：実装 ／ **タイムボックス**：1時間

### 目的

Claude Code が、変更のたびに自分で実装ミスを検出できる状態を作る。

### やること

- `scripts/check.ps1` を作成する
  - 既定：`ruff format --check`、`ruff check`、`pytest`（isaac マーカーを除外）
  - `-Sim` オプション：上記に加えて `pytest -m isaac`
  - いずれかが失敗したら、非ゼロの終了コードで終わる
- パッケージの骨格を作成する：`src/restorebot/core/`、`src/restorebot/sim/`（空の `__init__.py` でよい）
- `docs/experiments/TEMPLATE.md`（目的・方法・結果・結論・設計への影響）を作成する
- `scripts/experiments/` を作成する
- 可能であれば、Claude Code のフック（ファイルの編集後に ruff を実行）を `.claude/settings.json` に設定する

### 完了条件

- [ ] `.\scripts\check.ps1` が成功する
- [ ] わざと lint 違反を入れると `check.ps1` が失敗することを確認した
- [ ] `.\scripts\check.ps1 -Sim` で既存のスモークテストが通る

## [検証] RidgebackFranka の読み込みと台車の動かし方

- **種別**：検証 ／ **タイムボックス**：2.5時間

### 目的

RidgebackFranka を移動ロボットとして使えるかを確認し、台車への指令方法を決める。

### やること

- RidgebackFranka を headless で読み込む。Isaac Sim 6.1 のアセットには次の2種類があるので、両方を読み込んで違い（関節構成、物理の設定など）を比べ、どちらを使うかを決める
  - `Robots/Clearpath/RidgebackFranka/ridgeback_franka.usd`（従来の配置）
  - `Robots_Multiphysics/Clearpath/RidgebackFranka/ridgeback_franka.usda`（6.1 の Franka のサンプルはこちらの系統を使っている）
- 全関節の名前・種類・可動範囲・駆動方式（位置指令か速度指令か、ゲイン）を一覧にする。12自由度の内訳（台車3＋アーム7＋指2を想定）を確認する
- 台車の3自由度（x, y, 向き）に指令を与え、目標の姿勢へ移動させる。位置指令と速度指令のどちらが扱いやすいかを比較する
- 到達精度と所要時間を計測する（例：1m 前進、90°回転、斜め移動の3パターン）
- 障害物（箱）に向かって移動させたときの挙動（止まる／押す／すり抜ける）を確認する
- 移動中のアームの揺れなど、気になる挙動を記録する

### 完了条件

- [ ] `docs/experiments/` に、関節の一覧、指令方法の比較、到達精度、障害物に当たったときの挙動を記録した
- [ ] 移動の前後の画像を `outputs/` に保存し、目視で確認した
- [ ] 台車の指令方法の推奨案を1つ提示した

## [検証] アームの動作計画

- **種別**：検証 ／ **タイムボックス**：3時間

### 目的

RidgebackFranka のアームで、グリッパーを目標の位置・姿勢へ衝突なく動かす方法を決める。

### やること

- Isaac Sim 6.1 で推奨される動作計画の手段を調べる（cuMotion（`isaacsim.robot_motion.cumotion`。6.1 の Pick and Place サンプルが使用）、Motion Generation（Experimental）、cuRobo など）。非推奨の API は候補から外す（Lula（`isaacsim.robot_motion.lula`）は 6.1 では `extsDeprecated/` 配下）
- Franka 単体用の設定ファイルが RidgebackFranka のアームにそのまま使えるかを確認する（関節名の対応、台車の関節の扱い、アームの根元の位置の渡し方）。cuMotion に同梱されているロボットの設定は `franka` と `ur10` のみ
- 台車を原点以外の位置・向きに置いた状態で、机の上の目標点（5点程度）へグリッパーを移動させ、位置の誤差と所要時間を計測する
- 台車を動かした後でも、正しく目標へ到達できることを確認する（根元の位置の更新）

### 完了条件

- [ ] `docs/experiments/` に、調べた手段の比較、到達の成功率と誤差、所要時間を記録した
- [ ] アームが楽に届く範囲（台車から物体までの距離の目安）を記録した
- [ ] 動作計画の手段の推奨案を1つ提示した

## [検証] 停止状態での把持と配置

- **種別**：検証 ／ **タイムボックス**：2.5時間

### 目的

台車を止めたまま、机の上の物体を掴んで別の位置へ置けることを確認し、把持の成功率と失敗の傾向を把握する。

### やること

- 机と、Franka のグリッパーで掴める大きさ（幅 8cm 未満）の物体を2〜3種類（箱、円柱など）用意する
- 「物体の真上へ移動 → 下降 → 閉じる → 持ち上げる → 目標の真上へ移動 → 下降 → 開く → 退避」の手順を実装する（アームの動作計画の検証結果を使う）
- 物体の初期位置を少しずつ変えて10回試行し、成功率と配置の誤差を計測する
- 失敗した場合は原因（滑る、ずれる、衝突する など）を分類する。摩擦や質量の設定の影響も確認する

### 完了条件

- [ ] `docs/experiments/` に、10回試行の成功率、配置の誤差、失敗の分類を記録した
- [ ] 試行中の動画、または連番画像を `outputs/` に保存した

## [検証] 天井カメラと VLM による差分検出

- **種別**：検証 ／ **タイムボックス**：3時間
- **補足**：ロボットは不要。台車・アームの検証と並行して進められる

### 目的

「いつもの写真」と「今の写真」から、VLM が動いた物体と戻し先を特定できるかを確認する。

### やること

- 簡素な部屋（床・壁・机・棚）を単純な形状で作り、物体を4〜6個配置する
- 天井カメラ（RGB＋深度）の位置・画角・解像度を決め、作業範囲が写ることを確認する
- 「いつもの状態」と、物体を1〜3個動かした「散らかった状態」の画像のペアを、シードを固定して10組ほど自動生成する
- 使う VLM を決める（精度・速度・費用で比較。少なくとも1つは試す）
- 結果を JSON で受け取るプロンプトを作る（例：動いた物体の名前、今の場所、戻し先）。余裕があれば、物体名のリストを渡す場合と渡さない場合を比較する
- 動いた物体の検出の正解率（見落とし・誤検出）、応答時間、1回あたりの費用を記録する
- 画像の向き（上下・左右）が正しいことを確認する

### 完了条件

- [ ] `docs/experiments/` に、検出の正解率、応答時間、費用を記録した
- [ ] プロンプトと JSON の形式の案を作成した
- [ ] VLM の選定理由を記録した

## [検証] Isaac Sim の起動時間の短縮

- **種別**：検証 ／ **タイムボックス**：1時間
- **補足**：#5・#6 で判明。Isaac Sim の起動に毎回約 200 秒かかる（CLAUDE.md の記載は「2 回目以降は約 8 秒」）。ログでは、Windows のスマート アプリ コントロールが torch の DLL（`.venv\Lib\site-packages\torch\lib\shm.dll`）を阻止し、非推奨の拡張機能（`isaacsim.core.api`、`isaacsim.sensors.camera` など、`extsDeprecated/` 配下）の読み込みが失敗するたびに約 13 秒ずつ待っている

### 目的

Isaac Sim の起動時間を短くし、検証・開発の待ち時間を減らす。

### やること

- 起動時間の内訳をログで確認する（どの拡張機能の読み込みで、何秒待っているか。torch が原因かどうか）
- 対策を試して比べる（例：非推奨の拡張機能を読み込まない設定、torch を必要とする拡張機能の無効化）
  - スマート アプリ コントロールの設定を変える案は、PC の保護に関わるので、試す前に相談する
- 対策の副作用を確認する（これまでの検証で使った API・拡張機能が動くか、全チェックが通るか）

### 完了条件

- [ ] 起動時間の内訳と原因を `docs/experiments/` に記録した
- [ ] 起動時間を短くする方法（短くできない場合は、その理由と回避策）を記録した
- [ ] 対策を採用する場合は、スクリプトと CLAUDE.md の起動時間の記載を更新した
