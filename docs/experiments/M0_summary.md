## 2. 決まったこと

### ロボットとアセット

- **アセット**：`Robots_Multiphysics/Clearpath/RidgebackFranka/ridgeback_franka.usda`（Multiphysics 版。アセットサーバーから読み込む）（#2）
- **台車の姿勢**：台車の x・y・yaw の仮想関節はワールド基準なので、関節角 (x, y, yaw) ＝ 台車のワールド姿勢（#2）
- **シーンの読み込み時に変える物理の設定**（設計書に理由とともに書く）
  - 台車の x・y 関節の `physxJoint:jointFriction` を 0 にする（物理の開始前）。アセットのままでは速度指令が 8〜20cm 手前で止まる（#2）
  - 指（`panda_finger_joint1/2`）のドライブを剛性 2000・減衰 100・最大力 40N にする。アセット（剛性 1e7・最大力 1200N）では掴めない（#4。現実的な値かどうかは未決）

### 移動層（台車）

- **指令方法**：速度指令（`switch_dof_control_mode("velocity")` ＋ `set_dof_velocity_targets`）。上位の制御が作った速度を与える。上限 0.5m/s・1.0rad/s（#2）
- **台車の止め方の条件**：物体が台車の正面、中心から 0.55〜0.85m（前面から 0.1〜0.4m）に来るように止める。机は台車の前面の近く（10cm 程度）まで寄せる（#3）

### 操作層（アーム・把持）

- **動作計画**：cuMotion の RmpFlowController（Motion Generation の枠組み）。必須の 4 つの処理：`panda_link0` の姿勢を根元として渡して台車が動くたびに更新する、全 DOF の名前で対応させる、tool frame に `panda_hand` を明示する、台車本体を障害物に加える（#3）
- **台車が動いたら必ず `sync()`**（根元・台車の障害物・周囲の物体の更新）。忘れると 20cm・10° ずれる（#3）
- **待機姿勢**：台車座標で (0.4, 0, 0.95) に手先を真下に向けた姿勢（`panda_joint1`〜`7` = -1.261, -1.378, 0.182, -2.254, 0.229, 0.892, 0.228 rad）。移動中もこの姿勢にする（#3）
- **把持と配置**：`PickPlaceController`（8 段階の状態機械）の構成を使う。`approach_height = lift_height = 0.15m`、`controller_to_grasp_position = (0, 0, 0.1034)`、掴む物体は下降〜配置の間だけ障害物から外す。サンプルのコード（Apache-2.0）を移植するときはライセンスを明記する（#4）
- **対象物の想定（確認済みの範囲）**：幅 4〜5cm、高さ 10cm 以下、0.5kg 以下。手先を真下に向けて上から掴む（#4）

### エージェント層（VLM）

- **VLM**：Claude Sonnet 5.5（`claude-sonnet-5-5`、`effort=high`）をメインにする。Gemini Robotics-ER 2 は代わりの候補（#5）
- **呼び出し方**：`VlmClient` のインターフェース（`detect(before_png, after_png, prompt) -> VlmResult`）。座標はクライアントの境界でピクセル (u, v) にそろえる（#5）
- **応答の形式**：`moved_objects`（name、current_location、current_point、target_location、target_point）。物体名のリストを渡す（名前の揺れを防ぐ）（#5）
- **戻し先の 3 次元位置**：`target_point` の画素と「いつもの写真」の深度から逆投影して求める（#5。M3 で使う）
- **SDK**：`anthropic` は 0.x に留める（1.x は Isaac Sim の `idna==3.10` と衝突）。API キーは `.env` から読む（#5）

### カメラ

- **天井カメラ**：天井の中央、高さ 2.6m、真下向き（画像の上がワールドの +y、右が +x）。焦点距離 13.5mm / 水平アパーチャ 20.955mm（水平画角 75°）、1024 × 768、RGB＋深度（`distance_to_image_plane`）（#5）
- **撮影用のカメラ**：俯瞰（固定）＋追従（台車の後ろ上方）。1280 × 720、30fps（#6）
- **描画の注意**：物体を瞬間的に動かした直後は RTX の時間方向の処理で残像が残る。150 フレーム程度進めてから撮る（#5）

### 動画

- headless で、制御ループの中で 2 ステップごとに `CameraSensor` の画像を PNG で保存し、ffmpeg（libx264、CRF 18）で mp4 にする。カメラは 2〜3 台まで。PNG は mp4 にしたら消す（#6）

### 開発環境

- Windows のスマート アプリ コントロールはオン（設定は変更しない）。署名のない実行ファイル・DLL は阻止されることがある。再発したら #8 の案 A（非推奨の拡張機能を除いた experience）を検討する（#8）
- Isaac Sim の起動は標準の experience のまま（約 9 秒）（#8）
- ffmpeg は winget の `Gyan.FFmpeg`（FFmpeg 9.0.2、gyan.dev のビルド）を使う（#6 の後に切り替え。libx264・NVENC が使えることを確認済み）

## 4. 設計書の論点

設計書（`docs/design.md`）を書く前に決める必要がある問い。

1. **全体の流れ**：「教える → 頼む → 見比べる → 動く → 確かめる → 報告する」を、どの単位（状態機械、タスクの列）で実行するか。失敗したとき（掴み損ね、届かない）にどうするか
2. **物体と場面**：片付けの対象物の組（掴める大きさ、VLM が見分けやすい見た目）、置き場所（机・棚の天板）、部屋のレイアウト。会議室の場面（M4）をどう作るか
3. **知覚の差し替え**：M1〜M2 はシミュレータの真値、M3 は画像からの推定を使う。両方を同じインターフェースで差し替えられるようにする設計
4. **VLM の出力をロボットの目標にする方法**：VLM が答えた名前・画素を、シミュレータの物体と 3 次元の目標位置にどう対応させるか（真値の段階と推定の段階）。物体名のリストを「いつもの写真」から作るかどうか
5. **移動層**：止め位置の計算、経路計画の方法（地図の表し方、障害物からの距離）、経路追従（速度指令の作り方）、スタックの検知
6. **操作層**：`PickPlaceController` の移植の範囲、置くときの向き、置き場所がふさがっているときの扱い
7. **確かめる・やり直す**（M4）：片付けの後にもう一度 VLM で比べる条件と、やり直しの回数の上限
8. **評価**（M5）：指標（成功率、位置の誤差、所要時間、VLM の費用）、試行の条件と回数、シードの扱い
9. **動画**：撮影用のカメラの構成と、記録の部品（`src/restorebot/sim/`）の作り
10. **コードの構成**：`core` と `sim` の分け方、設定値（物理の設定、カメラ、VLM のモデル名）の置き場所、テストの方針
