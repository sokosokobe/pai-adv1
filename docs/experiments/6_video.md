# #6 動画の記録方法

- **Issue**：#6
- **日付**：2026-10-12
- **タイムボックス**：1時間 ／ **実績**：約0.8時間（16:12〜17:00）
- **検証用コード**：`scripts/experiments/video_record.py`（headless で連番画像を保存して mp4 にする）、`video_gui_capture.py`（GUI の録画機能 Movie Capture）、場面の共通処理 `video_scene.py`。計算は `video_common.py`（単体テスト `tests/experiments/test_video_common.py`）
- **証拠**：`outputs/m0_6/`（サンプル動画、連番画像、`summary.json`、ログ）

## 目的

1. 提出動画の素材を、headless でカメラの画像を連番で保存して mp4 にする方法で作れるか
2. GUI で録画する方法と比べて、画質・手間・所要時間はどうか
3. 撮影用のカメラ（俯瞰・追従など）を複数置いたときの負荷はどの程度か

## 方法

- Isaac Sim 6.1.0（pip 版）、物理 60Hz。場面は #5 の部屋（見た目だけ、衝突なし）に RidgebackFranka（Multiphysics 版）を置き、#2 の推奨（台車の x・y 関節の摩擦 0、速度指令、比例制御＋飽和 0.5m/s・1.0rad/s）で、部屋の手前側を「1.1m 前進 → 左へ 90° 旋回 → 戻る → 1.1m 後退」と動かした（10 秒で一巡。アームは既定姿勢のまま）
- 撮影用のカメラ（すべて 1280 × 720、30fps。`CameraSensor` の `rgb`）

  | 名前 | 置き方 | 焦点距離 |
  |---|---|---|
  | overview（俯瞰） | 部屋の奥・左の隅の天井付近 (-1.45, 1.05, 2.2m) から、台車の経路を見下ろす | 14mm |
  | follow（追従） | 台車の後ろ 1.3m・左 0.4m・高さ 1.9m から台車の 0.6m 前を見る。壁の内側に収め、指数移動平均（0.15/フレーム）でなめらかに動かす | 16mm |
  | ceiling（天井） | #5 の天井カメラと同じ位置・向き（真下） | 12mm |

- **headless の方法**（`video_record.py`）：物理の 2 ステップごとに各カメラの画像を取り、PNG（`compress_level=1`）で連番に保存した。その後、mp4 に変換した
  - ffmpeg（PC に入っている winget 版）の libx264（CRF 18、preset medium）と h264_nvenc（CQ 19、preset p5）
  - Isaac Sim 同梱の `omni.videoencoding`（`encode_image_file_sequence`、NVENC、外部の ffmpeg が不要）
  - 俯瞰と追従を ffmpeg の `hstack` で横に並べた 1 本（2560 × 720）
- **GUI の録画機能**（`video_gui_capture.py`）：Isaac Sim の Movie Capture（`omni.kit.capture.viewport`）で、俯瞰カメラを 300 フレーム、mp4 に直接録画した（RAY_TRACE＝リアルタイムの RTX）。台車の速度指令は物理のステップごとのコールバック（`PHYSICS_PRE_STEP`）で与えた。参考にしたのは、Isaac Sim 同梱の `skills/isaac-sim-remote/scripts/viewport_video.py`
- 負荷：カメラ 0〜3 台で同じ場面を別々のプロセスで動かし、撮影ループの所要時間（描画を含む `simulation_app.update`、画像の取得、PNG の保存）と GPU のメモリ（`nvidia-ml-py`、GPU 全体の使用量）を測った
- Windows のゲームバーや OBS での画面録画は、人の操作が必要なので試していない（手間を文章で比べた）

## 結果

### 1. サンプル動画（`outputs/m0_6/sample/`）

| ファイル | 内容 | 大きさ |
|---|---|---|
| `overview_follow.mp4` | 俯瞰と追従を横に並べたもの（2560 × 720、30fps、10.0 秒、300 フレーム） | 2.3MB |
| `overview_libx264.mp4` / `follow_libx264.mp4` / `ceiling_libx264.mp4` | カメラごと（1280 × 720、10.0 秒） | 1.2 / 1.6 / 1.2MB |
| `*_nvenc.mp4` / `overview_kit.mp4` | 同じ連番画像を NVENC、`omni.videoencoding` で変換したもの | 2.3〜3.0 / 17.6MB |

- 動画からフレームを取り出して目視で確認した。台車は経路を一巡し（最後の経由点まで到達）、俯瞰・追従の両方で常に画面に入っている。動いている間もブレや残像は見えなかった。天井カメラの向きは #5 と同じ（机が右上、棚が左）
- 画質：元の PNG と比べた PSNR は、libx264 で 52.4〜52.8dB、NVENC で 54.5〜55.3dB。どちらも見た目では区別できない
- 最初に置いた俯瞰カメラ（手前・右の隅）は台車の経路のすぐ上で、台車が画面の下端で切れた。反対側の隅に移した

### 2. カメラの台数による負荷（10 秒の場面、物理 600 ステップ・画像 300 フレーム）

| カメラ | 撮影ループの所要時間 | 実時間の何倍か | 描画（1 ステップ） | 画像の取得 | PNG の保存 | GPU のメモリ（全体） |
|---|---|---|---|---|---|---|
| 0 台 | 8.3 秒 | 1.21 | 13.5ms | - | - | 3.07GB |
| 1 台 | 16.1 秒 | 0.62 | 16.6ms | 0.7 秒 | 5.2 秒 | 3.40GB |
| 2 台 | 27.6 秒 | 0.36 | 20.6ms | 4.2 秒 | 9.9 秒 | 3.56GB |
| 3 台 | 36.4 秒 | 0.27 | 24.0ms | 5.9 秒 | 15.0 秒 | 3.92GB |
| 3 台（保存なし） | 21.3 秒 | 0.47 | 24.0ms | 5.9 秒 | 0 | 3.41GB |

- カメラ 1 台につき、描画が約 3.5ms/ステップ、PNG の保存が約 5 秒/300 枚（1 枚 17ms）増える。一番重いのは PNG の保存
- GPU のメモリは 3 台でも約 4GB（12GB のうち）。余裕がある
- 連番画像はカメラ 1 台・10 秒で約 270MB（PNG、圧縮レベル 1）。5 分ならカメラ 1 台あたり約 8GB になる
- mp4 への変換は速い：libx264 1.2〜1.4 秒、NVENC 0.6 秒、`omni.videoencoding` 4.4 秒（いずれも 300 フレーム）、横に並べる処理 1.8 秒
- 撮影は実時間より遅い（3 台で 0.27 倍）が、動画は物理の時刻で 30fps に並ぶので、再生すると実時間の速さになる

### 3. GUI の録画機能（Movie Capture）

- 録画そのものはできた：300 フレーム（1280 × 720）を 19.6 秒で mp4 にした（17.7MB、16Mbps の既定のビットレート）。物理も 600 ステップ進んだ
- **ただし、スクリプトで台車を動かせなかった**。Movie Capture は開始時にタイムラインを巻き戻すため、物理の状態（`Articulation` が使うシミュレーションのビュー）が消える。録画中はビューが作り直されず（"Play the simulation/timeline to re-initialize it"）、コールバックの中で `Articulation` を作り直しても読み書きできなかった。台車は初期位置（部屋の中央）に戻り、アームは制御されずに垂れ下がった（`outputs/m0_6/gui/gui_overview.mp4`）
- Isaac Sim 同梱のサンプルにも「タイムラインで動く場面用で、自前の制御ループの中では録画できない。制御ループの中では画面を画像で保存し、`encode_image_file_sequence` で変換すること」と書かれている。今回の結果はこれと一致する
- 画面録画（ゲームバー、OBS）は試していない。画面に表示された速さのまま録画されるので、描画が実時間より遅い場面（カメラ 1 台でも 0.62 倍）は遅く・カクついて見えるはず。録画の開始・終了とカメラの操作を人が行う必要があり、毎回同じ映像を作れない

### 4. 方法の比較

| | headless ＋連番画像＋ffmpeg（推奨） | GUI の Movie Capture | 画面録画（ゲームバー、OBS） |
|---|---|---|---|
| 画質 | 元の画像と見分けがつかない（PSNR 52dB 以上）。解像度・カメラを自由に選べる | 同じ RTX の描画。既定のビットレートは高い（17.7MB/10 秒） | 画面の解像度と GUI の表示に左右される（未検証） |
| 手間 | コマンド 1 つ。同じシードなら毎回同じ映像。カメラを何台でも同時に撮れる | 自前の制御ループと組み合わせられない（今回の場面では台車が動かなかった） | 人の操作が必要。毎回同じにならない |
| 所要時間（10 秒・1 台） | 撮影 16 秒＋変換 1 秒（起動を除く） | 20 秒（起動を除く） | 実時間（未検証） |
| 実時間より遅い場面 | 物理の時刻で並ぶので正しい速さで再生される | 正しい速さ | 遅く・カクついて見える |

### 5. 気づいたこと（環境）

- **Isaac Sim の起動に毎回約 200 秒かかった**（CLAUDE.md の「2 回目以降は約 8 秒」より大幅に遅い）。ログでは、非推奨の拡張機能（`isaacsim.core.api` など）が torch の読み込み（スマート アプリ コントロールによる `shm.dll` の阻止、#5 を参照）に失敗するたびに約 13 秒ずつ待っている。動画の作成に限らず、すべての検証・開発の待ち時間に影響する

## 結論

1. **推奨：headless で撮影用のカメラの画像を連番（PNG）で保存し、ffmpeg（libx264、CRF 18）で mp4 にする**
   - 自前の制御ループ（台車の速度指令、cuMotion、VLM の呼び出し）の中でそのまま撮れる。シードを固定すれば毎回同じ映像になる
   - 俯瞰・追従・天井など複数のカメラを同時に撮れ、編集で切り替えたり並べたりできる
   - 実時間より遅く動いても、動画は正しい速さで再生される
   - 画質は十分（PSNR 52dB 以上）で、ファイルは小さい（720p で 10 秒あたり 1.2〜1.6MB）
2. **カメラは 2〜3 台まで**にする。3 台でも GPU のメモリは約 4GB で、撮影は実時間の約 0.27 倍の速さ。提出動画（1〜5 分）なら、撮影は 5 分の場面で約 20 分。PNG はカメラ 1 台・5 分で約 8GB になるので、mp4 にしたら消す
3. **変換**：既定は ffmpeg の libx264。速さを優先するなら NVENC（2 倍速いが、ファイルが約 2 倍）。ffmpeg が使えない環境では、Isaac Sim 同梱の `omni.videoencoding`（`video_encoding.encode_image_file_sequence`）でも変換できる
4. **選ばなかった案**
   - GUI の Movie Capture：録画を始めるとタイムラインが巻き戻され、スクリプトから台車を制御できなくなる（NVIDIA のサンプルの注意書きとも一致）。タイムラインのアニメーションだけの場面（カメラを動かすだけの紹介映像など）には使える
   - 画面録画：人の操作が必要で、毎回同じにならず、表示が遅いとカクつく

## 設計への影響

- 動画の記録は、`video_record.py` と同じ形（制御ループの中で `CameraSensor` の `rgb` を 2 ステップごとに保存 → ffmpeg で mp4）を、本実装の `src/restorebot/sim/` に記録用の部品として作る。ffmpeg のコマンドを組み立てる処理は Isaac Sim に依存しないので、`core` 側に置ける
- 撮影用のカメラの基本の構成：俯瞰（固定）＋追従（台車の後ろ上方）。天井カメラ（#5）の映像も、VLM の入力の説明に使える
- 物体を動かした直後は描画が落ち着くまで待つ（#5）。動いている場面のブレ・残像は、今回は見えなかった
- **残ったリスク**
  - 長い動画（5 分）の撮影時間とディスク（PNG はカメラ 1 台あたり約 8GB）は試していない。必要なら PNG の代わりに JPEG で保存するか、撮影しながら ffmpeg に画像を渡す（パイプ）方法を検討する
  - 起動に約 200 秒かかる問題（スマート アプリ コントロールと torch）は、開発の効率に大きく影響する。対策（非推奨の拡張機能を読み込まない設定にする、など）を別の Issue で検討することを提案する
  - アームの動き（把持）を含む場面は撮っていない。描画の負荷は同じだが、cuMotion の計算の時間が加わる

## 決定事項（2026-10-12）

- **動画の作り方**：推奨案どおり、headless で撮影用のカメラの画像を連番（PNG）で保存し、ffmpeg（libx264、CRF 18）で mp4 にする
- **Isaac Sim の起動時間（約 200 秒）**：別の Issue で対策を検討する
